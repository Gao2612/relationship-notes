# 导入队列的存储决策

当前不把聊天导入队列持久化到宿主磁盘。正式聊天资料继续由关系手记客户端保存到浏览器 IndexedDB；宿主仅保留有界临时队列。为恢复重启前尚未消费的聊天而保存队列正文，会新增另一份聊天数据和新的删除/备份/迁移边界，改变现有隐私模型。

只保存队列版本、哈希或消费进度，无法在进程重启后还原消息正文，因此不声称提供“未消费聊天的重启恢复”。DSH 重启后，尚未消费的导入需要用户从原始资料重新触发；已经在关系手记中成功保存的数据由 IndexedDB 恢复。

本次改善：队列满 20 项时拒绝新导入并提示先消费，保留全部已有未确认记录；不再静默丢掉最早一项。工具说明和结果提示明确“临时队列、打开关系手记完成保存、重启清空未消费内容”。现有按版本 ack 的幂等语义继续使用。

将来如要持久化，应由用户明确选择宿主保管聊天，并单独设计数据目录、加密、清理、保留期限、重启恢复和重复消费保护。当前没有新增宿主聊天落盘。
