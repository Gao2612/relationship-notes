# 关系手记 3.1 复审与整改

日期：2026-11-01。本次是对 3.1.0 的代码、数据流、构建产物及交付说明复审；监听、替代 ExportWeChat、自动发送/主动搭话仍暂缓。

## 已确认并整改的问题

| 优先级 | 问题 | 整改 |
|---|---|---|
| 高 | 总评分与每日评分使用不同识别规则，部分纠正无法对齐 | 共用互动信号与计算函数；纠正索引统一；转述、否定、普通负面情绪更保守地处理。 |
| 高 | 共享快照更新后，旧候选可能继续引用已修改/删除的原消息 | 同步时复核来源 ID、身份、原文与时间；失效候选淘汰。 |
| 高 | 确认过的推测可能混入事实，删除条目又作为“资料更新”传给模型 | 工具按 facts/patterns/inferences 分层；草稿事实载荷排除推测和已删除条目。原聊天仍由用户单独管理。 |
| 高 | 画像响应只按文本和时间回查，重复来源可能串引用 | 捕获稳定 ID，并核验当前唯一消息与连续引用。 |
| 中 | 本人样例/计划迁移过滤空项后，附加元数据可能错位 | 每条先独立规范化并保留自己的元数据，再过滤限长。 |
| 中 | 解释模型的 delta 与完整 block 混合输出可能被截断 | 按块编号收集，完整块替换同块增量，过滤 reasoning，统一总长度限制。 |
| 中 | 显式空 contactId 退回当前联系人；导入 MiB 限制按字符计数 | 联系人参数严格校验；导入按 UTF-8 实际字节限制。 |
| 中 | 测试偏重源码字符串，无法发现产物 factory 初始化失败 | 执行完整 client bundle、factory、apply 与宿主入口；递归发现子目录测试。 |
| 低 | ZIP 安装与源码构建说明混在一起 | README 分开说明，安装包无需执行源码构建，升级需重载宿主服务。 |

客户端异步请求、保存后确认消费与刷新重放的细节见 [UI复审](REVIEW-UI.md)；数据与工具见 [数据复审](REVIEW-DATA.md)；构建和打包见 [工程复审](REVIEW-ENGINEERING.md)。自动测试和虚拟环境中的工厂执行不能代替真实 DSH 界面操作验收。

引用校验只能证明原文存在，不能证明模型解释在语义上成立；确定性措辞检查也不是完整的心理判断过滤器，仍需用户核对。

## 优先优化建议

1. **拆分视图并替换源码切片测试**：workspace.js 仍集中较多状态与页面组装。逐步抽出档案、回复、设置组件，改用组件行为与真实工厂测试，减少代码移动就导致测试失效的问题。
2. **建立不可变消息 ID**：对新导入消息赋持久 ID，旧资料采用兼容映射，减少内容指纹碰撞及同文消息歧义。
3. **共享范围预览**：开启 DSH 共享时列出联系人、时间范围、条数与截断情况；提供主动缩小范围的选择。现有权限不是某一个 DSH 聊天专属授权。
4. **长聊天性能**：按联系人/消息版本缓存分析，列表和证据分段加载；用真实大样本记录耗时，再决定存储拆分。
5. **自动化交付清单**：从 package.files 生成包与哈希清单，检查版本、入口和文件闭包，减少人工复制与旧产物混用。

## 建议新增的功能（尚未实施）

| 顺序 | 功能 | 具体收益 | 交付标准 |
|---|---|---|---|
| 1 | 证据跳转和上下文查看 | 点击画像/评分依据后定位原消息，并查看前后对话 | 重排、筛选后仍定位正确；来源已删除时明确提示。 |
| 2 | 资料变更与过期提醒 | 新旧城市、工作、计划冲突时给出对照，不自动覆盖；计划可标完成/取消 | 用户确认更新；保留历史；旧计划不再用作当前话题。 |
| 3 | 回复编辑反馈 | 用户主动把改好的草稿加入本人认可样例，逐步贴近个人表达 | 展示前后差异，可撤销；不自动把所有草稿当本人真实发言。 |
| 4 | 周/月沟通复盘 | 汇总真实话题、尚未回答的问题及待跟进事项 | 每条有依据；不输出好感概率或保证对方反应。 |
| 5 | 话题建议反馈 | 标记“合适/不合适/已聊过”，减少重复推荐 | 仅调整本机排序，不据反馈猜测对方心理。 |
| 6 | 单联系人交付与清理 | 独立导出、备份或删除一位联系人的数据 | 预览覆盖范围；包括档案、媒体、草稿及共享撤权。 |

建议先做证据跳转、资料变更管理、回复反馈。这三项直接完善当前已有能力，新增桌面依赖较少。其余能力在实际使用数据与界面验收后排序。
