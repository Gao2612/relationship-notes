## 概要

关系手记は、取り込んだ WeChat／QQ のチャット履歴を、連絡先プロフィール、日ごとのやり取りの根拠、関係分析に整理し、返信の下書きを手伝います。

- **ローカル優先**：チャット、プロフィール、下書き、自分のプロフィールは、ブラウザのローカル IndexedDB に保存されます。AI 機能を開始したときだけ、該当する文脈が DSH で設定したモデルサービスに送られます。
- **根拠を確認できる**：スコア、プロフィール項目、話題、振り返りの根拠は、すべて元のメッセージと前後の文脈を開いて確認できます。誤検出は除外・復元できます。
- **「好意の確率」は出さない**：どの指数も観察できるやり取りの過程をまとめたもので、「相手があなたを好きな確率」ではありません。

## 主な機能

### 現在の機能

**関係分析 v3（メインの分析）**

- 研究に基づく 6 つのやり取りの次元（応答性、自己開示、相互性、ポジティブな応答、主体的な関与、言語の同調）を週ごとに評価し、摩擦と修復で総合指数を割り引きます。
- ルール層は確認でき、同じ結果を再現できます。各次元を根拠の量に応じて中立に向けて縮小し、80% 区間を示します。チャットのない週は欠測として表示します。
- 任意の AI による文脈評価：どの評価にも原文の逐語引用が必要で（ホストで照合）、限られた重みで統合します。ルールと食い違えば確認を促し、AI だけで境界線による上限を発動することはできません。
- 長期推移：EWMA、重み付きトレンドと区間、変化点と期間を示し、どの次元が変化をもたらしたかを示します。
- 根拠は「原文の事実／AI の引用／AI の推論」の 3 列に分け、どれも原文の文脈を開けます。ルールと式は[採点と分析のルール](#採点と分析のルール関係分析-v3)をご覧ください。

**ルールによる判定と日ごとのスコア（好感手がかりスコア v2.3）**

- 文脈を考慮した採点：直前の質問・提案・話題をもとに、回答、提案の受け入れ、話題の引き継ぎを判定し、有効な応答のあったターン数で採点します。
- 一度だけの相づちや笑いは中立として扱い、有効な応答のないターンが 3 回続いたときだけ短い返信のペナルティを適用します。
- 口語的な自己開示は主語の変化や自然な言い回しに対応し、システムメッセージ、メディア、プレースホルダーだけのテキストは除外します。
- やり取り指標ページでは、関与スコア、ポジティブ表現の根拠、仕事／日常／混合の場面別統計を分けて表示します。ポジティブ表現には礼儀・支持・親しみの段階を表示します。
- 直前の気持ちや良い知らせに対する支持的な応答を判定し、気持ちの開示と単なる事実の開示は別々に重み付けします。
- 10 種類の判定は、元のテキストとの照合、除外、復元ができ、修正すると関連する件数とスコアも更新されます（v2.3 と v3 のルール層の両方）。
- ポジティブな信号はターンごとに重複を除いて上限を設け、サンプルが少ないスコアは 32 に向けて縮小します。返信の遅れは記述統計のみとし、説明は摩擦のペナルティを増やしません。
- スコア内訳の加点・減点の合計は最終スコアと一致し、ターン数の数え方と月・年の集計は同じ定義を使います。式は[付録](#付録好感手がかりスコア-v23日ごとの経過とやり取りスコアで引き続き使用)をご覧ください。

### プロフィールとコミュニケーション機能

- プロフィール、スコア、話題、振り返りの根拠から、元のメッセージと前後の文脈を開けます。
- 連絡先の情報と自分の計画には、有効期限、完了、取り消し、期限切れ、再開を設定できます。終わった計画は現在の提案とモデルの文脈から外れます。
- 編集した下書きは、自分の表現の例として明示的に保存でき、その保存を取り消すこともできます。
- 話題は「已经聊过 / 不合适」（もう話した／ふさわしくない）として非表示にでき、復元もできます。
- 行動記録に週・月の振り返りを追加し、実際の話題、その後の応答がなかった質問、現在のフォローアップ項目をまとめます。
- 設定で、DSH と共有する日付範囲と件数をプレビュー・制限できます。適用後は再承認が必要です。
- 新しいメッセージには永続 ID を使い、古い参照との互換性も保ちます。独立したビューと自動の納品チェックリストを追加しました。

詳しくは [機能と入口の説明](docs/FEATURES-3.2.md)（中国語）をご覧ください。画面のスクリーンショットには実在の連絡先とチャット内容が含まれるため、リポジトリでは公開していません。

### 機能一覧

主な機能と入口は次のとおりです。

1. **連絡先プロフィール**（联系人档案）：モデルが提案したプロフィール情報を確認・承認します。話し方、境界線、フォローアップ、推測の手がかりを分けて表示し、有効期限、アーカイブ、削除に対応します。
2. **関係分析**（关系分析。新機能、「记录与评分」（記録と採点）の既定ページ）：6 次元の週ごとの評価、80% 区間付きの総合指数、AI 評価、長期トレンドと変化点、3 列の根拠表示。
3. **日ごとの経過**（每日历程）：日ごとのやり取りスコア、実際の話題、「その後の応答がない」質問を表示し、元のメッセージと前後の文脈を開けます。
4. **やり取りスコア**（互动评分）：関与スコア、ポジティブ表現の件数、回答と引き継ぎのターン、場面別の結果を表示します。根拠を開くと表現の段階を確認でき、誤検出を除外・復元できます。
5. **採点ルール**（评分规则）：式、重み、条項を表示し、一文ずつの説明を開けます。
6. **記録一覧**（记录列表）：すべてのチャット記録を、ページ送り・検索・新しい順で閲覧し、原文の位置に戻れます。
7. **会話**（会话）：連絡先ごとに会話全体、画像、音声を閲覧できます。右側に下書き、関連ページ、編集エリアを固定表示します。
8. **コミュニケーション支援**（沟通辅助）：誠実／気軽／簡潔の 3 つのスタイルで下書き候補を作成し、引用と不確かさの説明を付けます。自分の表現例として保存できます。
9. **話題の提案**（话题建议）：話題を作成し、「已经聊过 / 不合适」で非表示にでき、いつでも復元できます。
10. **行動計画**（行动计划）：目標を手動で追加し、有効期限を設定して、完了、取り消し、期限切れ、再開を記録できます。
11. **週・月の振り返りと設定**（周月复盘与设置）：実際の話題、未回答の質問、フォローアップをまとめます。設定には、モデルの選択、文字サイズと密度、バックアップの書き出し・復元、DSH との共有範囲のプレビューがあります。

## 画面と操作

2026 年 11 月の画面更新では、既存の機能とデータ構造をすべてそのまま維持しています。

- **ビジュアルシステム**：青磁色（操作と選択）、蓮色（関係のパルス表示専用）、藍色（AI）、琥珀色（推測・要確認）、朱色（拒否と摩擦）。色はすべてホストの背景色・文字色から算出するため、ライトテーマとダークテーマで一貫します。数字にはオールドスタイルのセリフ書体（Palatino / Georgia）を使います。
- **関係の概要バー**：ヘッダーに、相手のアバターと名前、メッセージ数、最後にチャットした日付、直近 20 週のやり取り指数の折れ線と最新値を表示します。クリックすると関係分析を開きます。
- **ナビゲーション**：第 1 階層のナビゲーションに線画アイコンを付けました。スマートフォンの幅では画面下部の固定タブバーに移動します（セーフエリア対応）。
- **階層**：特集カード（初回ガイド、関係分析の概要）＞平面的なセクション＞薄い背景の項目。影はメニュー、通知、ドロワーなどの浮かぶ要素だけに使います。
- **取り込み**：ファイルのドラッグ＆ドロップに対応しています。発言者が 2 人で「自分」を判別できるときは本人の割り当てを自動で選び、「⇄ 交换」（入れ替え）で入れ替えられます。取り込み元のフィルター（すべて／WeChat／QQ）はセグメントコントロールで、記録のない取り込み元は無効になります。
- **会話**：狭い画面（900px 以下）では会話リストがドロワーとして開き、背景をタップするか Esc で閉じます。「☰ 列表」（リスト）ボタンの状態は実際の表示状態と一致します。広い画面では「工具」（ツール）で右側のペインを折りたためます。返信の意図の入力欄では Ctrl/⌘ + Enter で返信を作成できます。
- **通知とアニメーション**：状態の通知は画面下部に浮かぶ通知として表示します（通常の通知は 6 秒で閉じ、エラーは残ります）。ページの切り替えは短いフェードが 1 回だけです。`prefers-reduced-motion`（視差効果を減らす設定）に従い、タップ領域は 44px を確保し、コントラスト比は 4.5:1 以上です。

## インストール

### ビルド済み ZIP のインストール

リリースまたはローカルビルドで作成したインストール用 ZIP を、専用のフォルダーに展開します。フォルダー内に `package.json`、`index.js`、`client.js`、`cordis.patch.yml` があることを確認してください。DSH のローカルプラグインのインストール／読み込みの入口でそのフォルダーを選び、关系手记とその「定制模块」コンテナの依存を有効にしてから、ホストのプラグインサービスを再読み込みします。再読み込みの入口がない DSH では、DSH を再起動してください。パッケージには `client.js` が含まれているため、pnpm のインストール、ビルド、テストは不要です。

アップグレードの前に、关系手记のバックアップを書き出してください。新しく展開したフォルダーをローカルプラグインの読み込み先に指定し、ホストサービスを再読み込みします。ページを更新するだけでは、古いホストのルート（たとえば関係分析に必要な `/affinity-analysis` ルート）が使われたままになることがあります。その後、「定制模块」で关系手记を開きます。インストール用 ZIP は実行用パッケージで、ビルドやテストのツール一式は含まれません。開発にはソースリポジトリを使ってください。

### ソースからのビルドと検証

完全なソース（`build.mjs`、`verify-v3.mjs`、`pnpm-lock.yaml`、テストファイルを含む）を取得し、Node.js と pnpm を使います。検証は Node.js 22 で行いました。

```sh
pnpm install --frozen-lockfile
pnpm run build
pnpm test
```

ビルドは明示的な ESM モジュールと esbuild を使い、リポジトリ外のプロトタイプファイルには依存しません。`client.js` はリポジトリで管理している生成物です。クライアントのソースを変更したら、再ビルドして一緒にコミットしてください。インストール用パッケージにはこの生成物が含まれます。ソースの層構造と依存の向きは [アーキテクチャと保守の境界](docs/ARCHITECTURE.md)（中国語）をご覧ください。

### リリース用パッケージの作成

ビルド後、配布するファイルをプレビューしてから、インストール用パッケージを作成できます。

```sh
node tools/package-release.mjs --out <新しい出力フォルダー> --dry-run
node tools/package-release.mjs --out <新しい出力フォルダー>
```

パッケージツールは Windows PowerShell と .NET の圧縮ライブラリを使います。リリース用のファイル一覧に従って内容を選び、依存パッケージ、テスト、過去のアーカイブを除外して、ZIP、SHA256、ファイルごとの一覧を作成します。同じ名前の出力がすでにある場合は上書きせずに中止し、ソースがクライアントの生成物より新しい場合は先に再ビルドが必要です。

## 使い方

- DSH の「定制模块」で关系手记を開き、チャットファイルを取り込んで（ドラッグ＆ドロップも可）、双方の本人割り当てを確認します。
- 連絡先プロフィールで、モデルが確認待ちにした項目を確認し、承認、編集、アーカイブ、削除のいずれかを行います。話し方、境界線、フォローアップ、推測の手がかりは分けて表示されます。
- 「记录与评分 → 关系分析」（記録と採点 → 関係分析）で、ルール層の結果を確認します。「AI 分析」を押すと DSH のモデルが週ごとに評価します（いつでも取り消し可能）。結果は週ごとにキャッシュされます。
- 設定で、自分の口調、口癖、興味、計画、境界線、承認済みの表現例を管理します。返信の作成では、これらの情報に加え、誠実に表現する、境界線を尊重する、探りを入れて関係を試さない、といった原則を参考にします。
- やり取りスコアは原文まで開いて確認でき、誤検出を除外・復元できます。指数は表現の手がかりをまとめたもので、好意の確率ではありません。
- 返信欄では誠実／気軽／簡潔のスタイルを選べ、引用と不確かさを付けた複数の解釈と返信の方向性を自動で提案します。
- DSH のメインチャットからプロフィールを読ませたい場合は、「允许 DSH 读取当前联系人」（DSH に現在の連絡先の読み取りを許可）を明示的にオンにします。承認済みのプロフィールの読み取り、共有された最新 500 件までのメッセージの検索、確認待ち候補の提案ができます。共有範囲は、現在のローカル DSH ホスト内のツール会話です。詳しくは [プロフィールツールの説明](docs/PROFILE-TOOLS.md)（中国語）をご覧ください。
- プロジェクトのバックアップは、メディアを含めるかどうかを選べます。旧形式のバックアップも復元できます。

WeChat／QQ の監視、ExportWeChat の読み取りを置き換える独自機能、自動送信、自分から話しかける機能は開発を保留しており、[調査計画](docs/CAPTURE-RESEARCH.md)（中国語）があるだけです。既存の ExportWeChat の JSON／HTML ファイルの取り込みは引き続き使えます。

## DSH との互換性

| ホスト | 状態 | 説明 |
| --- | --- | --- |
| DSH デスクトップ版（`subdsh` コンテナあり） | 対応 | ID `relationship-notes` のサブページとして登録します。登録 ID、ラベル、順序はこれまでと同じです。 |
| npm 公開版 DSH Web（`@deepseek-ai/dsh` 0.2.2-rc.1 で確認） | 対応 | ホストに `subdsh` がない場合は、ネイティブのサイドバーに同じ名前のパネルを登録するため、ホストの起動を妨げません。ダークテーマは `--dsw-alias-*` トークンで対応しています。 |

- **コンテナの契約**：トップレベルで宣言するのは `inject: ['locale']` だけです。`subdsh` はプラグイン内の入れ子の inject で待機し、必須の依存にはしていません。
- **ホストのルート**：`/api/relationship-notes/` 以下の返信、取り込み、プロフィール、解釈、`affinity-analysis` の各ルート。詳しくは [ホスト API の説明](docs/HOST-API.md)（中国語）をご覧ください。
- **テーマ**：色はホストのテーマ変数から算出します（`--dsw-alias-*` のフォールバックを含む。`src/host-tokens.js`）。ライト／ダーク × PC／スマートフォンの 4 通りすべてを、実際の DSH Web で確認しました。
- **モデル**：AI 機能は DSH で設定したモデルサービス（`llm.prepareCall`）を使います。API キーが未設定の場合、AI のリクエストは失敗します（実測では 502 が返りました）が、ルール層の機能には影響しません。
- 既知の制限は [既知の問題](docs/KNOWN-ISSUES.md)（中国語）をご覧ください。

## 採点と分析のルール（関係分析 v3）

「记录与评分 → 关系分析」（記録と採点 → 関係分析）はプラグインのメインの分析ページで、ヘッダーの関係パルスの折れ線も同じ結果を使います。この節はコードと項目ごとに対応しています。対象は `src/affinity/`（ルール層、モデル、長期推移）と `affinity-service.js`（AI のルートと検証）で、モデルのバージョンは `3.0` です。

v3 は「好感度」を 1 つの数値では出しません。研究に基づく 6 つのやり取りの過程と、摩擦と修復を週ごとに評価し、ルール統計、AI による文脈評価、長期推移、項目ごとの原文の根拠を 1 ページにまとめます。どの指数も**観察できるやり取りの過程**をまとめたもので、「相手があなたを好きな確率」ではなく、愛着のタイプや性格の診断もしません。

### 計算の流れ

1. **ターンと週**：メッセージをターンにまとめ、双方の観察できるやり取りの事実を週ごと（月曜始まり、上海時間）に集計します。
2. **ルール層**：6 つの次元それぞれの元の値 $x$（0〜1）と根拠の量 $n$、摩擦の強さ、境界線を計算します。
3. **縮小**：各次元を根拠の量に応じて中立値 0.5 に向けて縮小し、標準誤差を求めます。
4. **AI 層（任意）**：「AI 分析」を押すと、モデルが週ごとに基準付きの尺度で評価します。逐語引用の付いた評価だけを、限られた重みで統合します。
5. **総合指数**：重み付き平均 × 摩擦による割引。明確な境界線のある週は上限 30 とし、80% 区間を示します。
6. **長期推移**：欠測、EWMA、トレンド、変化点、期間。
7. **説明**：各次元を「原文の事実／AI の引用／AI の推論」の 3 列で表示し、どれも原文の前後の文脈を開けます。

### ターン、会話のまとまり、週

- 採点には 2 人のテキストメッセージだけを使い、システムメッセージ、テキスト以外のメディアの記録、プレースホルダーだけのテキストは除外します（日ごとのスコアと同じ）。
- 同じ人が 3 分以内の間隔で続けて送ったメッセージは 1 つのターンにまとめます。最初の発言、または前のターンの終わりから 120 分以上空いた発言で新しい会話のまとまりが始まり、そのターンを「自分から話しかけた」1 回と数えます。
- 時刻は上海時間で日付に割り当て、さらに月曜始まりの週に割り当てます。メッセージが 1 件もない週はスコアを作らず、推移では欠測（0 点ではない）として表示します。
- 相手のターンの回答、引き継ぎ、摩擦、説明、おざなり・情報量が少ない、の判定と手動修正は、日ごとのスコアと同じ判定を使います（[付録](#付録好感手がかりスコア-v23日ごとの経過とやり取りスコアで引き続き使用)を参照）。そのため、両者の原文の根拠は一致します。
- v3 ではさらに 3 つを追加しています。自分の「つながりの誘いかけ」に対して相手が向き合ったか（支持や聞き返しを含む）、自分の良い知らせの場面、よくある謝罪・釈明の言い回しを修復として扱うこと（摩擦を軽くする方向にだけ働きます）です。

**つながりの誘いかけ（bid）**：自分が質問または自己開示をしたターンです。相手の次のターンの応じ方を 4 種類に分けます。

| 種類 | 条件 |
| --- | --- |
| 未返信 | 次のターンが相手のものではない、または 24 時間以上後。応答性の分母には入れない（テキストチャットは非同期のことがあるため） |
| 対立（against） | 相手のターンに明確な拒否・境界線、または摩擦が含まれる |
| 向き合う（toward） | 相手が回答または引き継いだ。または支持・具体的な感謝を示した（ポジティブの重み 4 以上）。または同じまとまりの中でその話題について聞き返した |
| それる（away） | 上記以外（自然な話題の切り替えの場合も、判定漏れの場合もある） |

**良い知らせの場面**：自分のターンに一人称の「我」（わたし）と良い知らせの語（「通过了」合格した、「拿到」もらえた、「升职」昇進した、「终于」ついに、など）があり、相手が 24 時間以内に応じた場合を 1 回の機会と数えます。相手の応答に摩擦がなく、支持・具体的な感謝（ポジティブ 4 以上）であるか、質問や回答・引き継ぎと一緒にポジティブな表現（ポジティブ 1 以上）がある場合は、積極的・建設的な応答と数えます。

### 6 つの次元とルール層の式

相手のターン数を $t$ とします。数はすべてターン数です（同じ種類の信号は 1 ターンにつき 1 回だけ数えます）。

| 次元 | 重み | ルール層の元の値 $x$ | 根拠の量 $n$ | 主な根拠 |
| --- | --- | --- | --- | --- |
| 応答性 | 0.28 | toward ÷ (toward + away + against) | 自分の誘いかけのうち返信があった回数 | Reis ら 2004；Laurenceau ら 1998；Gottman & Driver 2005 |
| 自己開示 | 0.18 | min(1, (相手の開示 + 0.5 × 相手の気持ちの開示) ÷ (0.6 × $t$)) | $t$ | Collins & Miller 1994；Laurenceau ら 1998 |
| 相互性 | 0.16 | 開示率、質問率、話しかけの回数の 3 つについて $1-\lvert a-b\rvert/(a+b)$ を求めた平均 | 双方の開示、質問、話しかけの回数の合計 | Sprecher ら 2013 |
| ポジティブな応答 | 0.14 | 0.5 × min(1, 相手のポジティブ点 ÷ 2$t$) + 0.5 × 良い知らせに積極的な応答があった割合。良い知らせの場面がなければ前の項だけ | $t$ + 良い知らせの機会の数 | Gable ら 2004 |
| 主体的な関与 | 0.14 | 相手から話しかけた割合と、min(1, 相手の誘いかけのターン ÷ 0.5$t$) の平均 | 双方の話しかけの回数 + $t$ | Gottman & Driver 2005；Stafford & Canary 1991 |
| 言語の同調 | 0.10 | 9 種類の機能語の 100 字あたりの使用率について $1-\lvert p_1-p_2\rvert/(p_1+p_2)$ を求めた平均（LSM、中国語の近似語彙、最長一致）。どちらかが 40 字未満なら計算しない | min(12, ⌊少ない方の文字数 ÷ 20⌋) | Ireland ら 2011 |

- 相互性の開示率と質問率は「その種類のターン ÷ その人のターン」で、話しかけは回数をそのまま比べます。釣り合っているかだけを見て、どちらが多いかは見ません。
- 相手のポジティブ点：各ターンで最も強いポジティブ表現を採用します。礼儀・絵文字 1、支持や具体的な感謝 4、直接的な親しみ 6 です。
- 相手の誘いかけのターン：相手が質問または開示をしたターンです。
- ある次元に計算できるデータがない場合、$x$ は欠測とし、縮小後は 0.5 になります。
- 返信の遅れとメッセージの長さは、どの次元にも入れません（返信が遅い、メッセージが短いことは、コミュニケーションの習慣や愛着の違いと関係するため。Morey ら 2013）。

**摩擦と修復**（重み付きの次元ではなく、総合指数への割引）：

$$
F_{\text{raw}}=\min\!\left(1,\ \frac{2\,(c+0.5\,e)}{\max(4,t)}\right),\qquad
F_{\text{rule}}=F_{\text{raw}}\times(1-0.5\,\rho),\qquad \rho=\min\!\left(1,\frac{r}{c}\right)
$$

$c$ は相手の摩擦のターン、$e$ はおざなり・情報量が少ないターン、$r$ は説明、和解、よくある謝罪のターンです（$c=0$ のときは $\rho=0$）。根拠：Gottman & Levenson 1992；Salvatore ら 2011。

**境界線**：相手のターンに、手動で除外されていない明確な拒否や連絡をやめてほしいという表現があれば、その週に境界線による上限を適用します。

### 縮小と区間

各次元は、ベータ二項モデルの経験ベイズの形で、中立の事前値 0.5 に向けて縮小します（$k=4$）。

$$
\hat d=\frac{n\,x+k\cdot0.5}{n+k},\qquad \mathrm{SE}=\sqrt{\frac{\hat d\,(1-\hat d)}{n+k}}
$$

根拠が少ないと推定値は自然に 0.5 に近づくため、1〜2 文だけで極端な値になることはありません。摩擦の事前値は 0（根拠がなければ摩擦なし）で、$\hat F=\dfrac{t\,F_{\text{rule}}}{t+4}$ です。

### AI による文脈評価と統合

「AI 分析」を押すと、プラグインは週ごとにチャットを DSH で設定したモデルに渡します（ルート `POST /api/relationship-notes/affinity-analysis`、温度 0.1、最大 3500 トークン、タイムアウト 90 秒）。いつでも取り消せます。

- **送る内容**：1 週につき最大 80 件、1 件につき最大 300 字です。それを超える場合は、相手のターンのうち開示、摩擦、修復、境界線、強いポジティブ（4 以上）、質問を含むものと、その直前の自分のターンを優先して残し、残りは時間に沿って均等に抽出して、モデルに抽出の割合を伝えます。前の週の AI の要約は背景として渡します（根拠には使えません）。相手のメッセージがない週は送りません。
- **尺度**：応答性、自己開示、相互性、ポジティブな応答、主体的な関与、摩擦のそれぞれに 1〜5 の整数を付け、根拠が足りなければ null とします。確信度は低・中・高です。摩擦は向きが逆（1 = 摩擦なし）で、その週の摩擦の後に修復があったか（repaired）も返します。プロンプトでは各次元に 1／3／5 の基準を示しています。
- **出力の条件**：null 以外の評価には 1〜3 件の引用を付け、引用は該当メッセージの原文から逐語で連続した部分でなければなりません。note はその文が何をしたかだけを書き、inference は考えられる解釈を不確かな言い回しで書き、alternatives には少なくとも 1 つの別の解釈を書きます。
- **ホストでの検証**（1 つでも違反があればその週全体を拒否し、502 を返す）：許可された次元だけ。評価は 1〜5 の整数か null。確信度は決められた値のどれか。null 以外の評価には引用が 1 件以上。引用は逐語で一致。境界線の引用は相手のメッセージからだけ。好意の確率やパーセント、「肯定/一定/证明……喜欢你」（きっと／証明……あなたが好き）のような断定的な言い回し、愛着のタイプや性格の診断は拒否します。

AI の評価 $r$ は $a=(r-1)/4$ に変換します。確信度の重みを $c_{\text{AI}}\in\{0.5,\,1,\,1.5\}$（低・中・高）とし、疑似カウントは $m=4\,c_{\text{AI}}$ です。

$$
\tilde d=\frac{n\,x+k\cdot0.5+m\,a}{n+k+m},\qquad
d=\hat d+\mathrm{clip}\big(\tilde d-\hat d,\ -0.25,\ 0.25\big),\qquad
\mathrm{SE}=\sqrt{\frac{d\,(1-d)}{n+k+m}}
$$

- 引用のない評価や rating が null の評価は使わず、その次元はルール層だけで計算します。言語の同調は AI の評価を受け付けません。
- ルール層に値があり、$n\ge3$ かつ $\lvert a-x\rvert>0.35$ の場合は、「ルールと AI が一致しません。確認してください」と表示します。
- 摩擦も同じように統合し（事前値 0）、動かせる幅も同じく ±0.25 です。AI が「修復あり」と判定した場合は、摩擦にさらに × 0.75 をかけます。
- **境界線による上限は、ルール層だけが発動します。** AI だけが境界線を検出した場合は、手動での確認を促す表示を出すだけで、指数は変えません。
- 結果は週ごとに連絡先のデータへキャッシュし、その週のメッセージの指紋と結び付けます。その週のチャットが追加・編集されると、自動的に分析待ちに戻ります（手動修正はルール層にだけ影響し、ルール層の結果はすぐに再計算されます）。2 週続けてリクエストが失敗したら止め、モデルが使えない状態で週ごとに繰り返しリクエストしないようにします。

### 総合指数、区間、信頼度

$$
P=\frac{\sum_k w_k d_k}{\sum_k w_k},\qquad
\mathrm{SE}_P=\frac{\sqrt{\sum_k (w_k\,\mathrm{SE}_k)^2}}{\sum_k w_k},\qquad
I=100\times P\times(1-0.6\,F)
$$

- 80% 区間：$100\times\mathrm{clip}(P\mp1.2816\,\mathrm{SE}_P,\,0,\,1)\times(1-0.6F)$。
- ルール層の境界線がある週は、指数と区間の上限・下限のどれも 30 を超えません。指数は四捨五入した整数（0〜100）です。
- 信頼度：相手のターンが 20 以上かつ応答性の根拠が 5 以上なら「高」、相手のターンが 8 以上なら「中」、それ以外は「低」です。

重みは理論上の重要度の順に並べつつ、ほぼ等しくしています。応答性は親密化の過程の中心的な媒介要因なので 0.28、開示、相互性、ポジティブな応答、主体的な関与がそれに続き、言語の同調は中国語の語彙が近似で根拠が 1 つの研究に限られるため最も低い 0.10 です。ラベル付きデータで当てはめられない場合、このような「不適切な線形モデル」のほうが主観的な細かい調整より頑健です（Dawes 1979）。重みは**実際の結果ではまだ較正していません**。

### 長期推移

- **欠測**：チャットのない週は欠測として残し、トレンドや変化点の計算には使いません。
- **平滑化**：EWMA（$\lambda=0.3$）。欠測の週は前の週の平滑値を引き継ぎます。
- **トレンド**：データのある直近 8 週以内について、重み $1/\max(4,\mathrm{SE}^2)$ の重み付き最小二乗で求めます。傾きの単位は「点／週」で、80% 区間を示します。4 週以上必要です。区間の下限が 0 より大きく傾きが 1 以上なら「上昇」、区間の上限が 0 より小さく傾きが −1 以下なら「下降」、それ以外は「横ばい」です。
- **変化点**：自己始動型の両側 CUSUM（$k=0.5$、$h=3$）。基準値は前の変化点以降（2 週以上）の平均です。ノイズの大きさは $\sigma=\max(3,\ \mathrm{MSSD},\ 0.5\times\text{SE の中央値})$ で、MSSD は隣り合う週の差から推定し、変化そのものをノイズに含めないようにしています。データのある週が 6 週以上で使い、変化の始まりは同じ向きのずれが続いた最初の週までさかのぼります。
- **期間**：変化点で区切り、期間ごとの平均指数と各次元の平均を示し、影響の大きい要因を最大 3 つ挙げます（影響 = 100 × 重み × 次元の変化。摩擦は −30 × 摩擦の変化。|影響| が 0.5 以上のものだけ）。

これらはすべて統計的な記述であり、関係についての結論ではありません。

### 説明可能な根拠

各次元には定義、ルールの式、研究の出典を示し、3 列で表示します。

- **原文の事実**：ルール層の統計と、それに対応する原文。各次元最大 6 件、種類ごとに最大 2 件で、良い例と悪い例の両方が見えるようにしています。
- **AI の引用**：ホストが逐語で照合した原文と、その客観的な説明。
- **AI の推論**：考えられる解釈、確信度、別の解釈。異なるスタイルで表示します。

どの原文も前後の文脈を開いて確認できます。

### 限界

- テキストには口調、スタンプの意味、音声、対面でのやり取りがありません。仕事の文脈、方言、皮肉は誤判定されることがあります。
- 中国語の LSM は近似の機能語リストを使い、単語分割はしていません。
- 重み、飽和パラメーター、縮小の強さ、動かせる幅の上限は製品としてのパラメーターで、実際の関係の結果では較正していません。
- LLM の評価にはばらつきがあり、モデルによって結果が異なることがあります。

設計の全体、研究の出典、今後の較正の計画は [関係分析 v3 の設計説明](docs/AFFINITY-V3.md)（中国語）をご覧ください。

## データとモデル

チャット、プロフィール、下書き、自分のプロフィールは、ブラウザのローカル IndexedDB に保存されます。モデルによる返信、プロフィールの整理、履歴の自動分析、「关系分析」の AI 分析を開始すると、該当するチャットの文脈とデータが DSH で設定したモデルサービスに送られます。自動分析は状態表示エリアで一時停止・再開できます。プロフィールの共有をオンにすると、現在の連絡先の範囲を限ったスナップショットがホストのメモリに一時保存されます。共有をオフにするか連絡先を切り替えると取り消され、同期を止めてから 60 秒で期限切れになります。ホストはこのスナップショットをディスクに保存しません。

取り込みツールはメモリ上のキューを使います。再起動の前に処理が終わっていることを確認してください。詳しくは [取り込みキューの設計](docs/IMPORT-QUEUE-DECISION.md)（中国語）をご覧ください。バックアップにはチャットのデータが含まれるため、ご自身で大切に保管してください。リポジトリには、ユーザーのチャットの書き出し、連絡先プロフィール、メディア、認証情報、個人のバックアップは含まれていません。

## 付録：好感手がかりスコア v2.3（日ごとの経過とやり取りスコアで引き続き使用）

この付録では、日ごとに計算する「好感手がかりスコア v2.3」を説明します。関係分析のメインの指標は前述の [v3 の指数](#採点と分析のルール関係分析-v3)です。v2.3 は「每日历程」（日ごとの経過）、「互动评分」（やり取りスコア）、「评分规则」（採点ルール）、「打分依据」（採点の根拠）などのページで引き続き使われており、相手のターンの判定と手動修正は v3 のルール層の入力にもなっているため、説明の全体を残しています。両者は定義が異なるため、直接比較しないでください。

好感手がかりスコアはローカルのルールで計算し、モデルは呼び出しません。項目ごとに確認できます（画面の「评分规则」（採点ルール）と「打分依据」（採点の根拠）の 2 ページはこの節と一致します）。現在の式は v2.3 です（2026 年 11 月から、質問の上限 +10、自己開示の上限 +12、摩擦の後の説明に最大 +4 の独立した加点。v2.1 の上限 8／10 は使っていません）。

このスコアは観察できるコミュニケーションの手がかりをまとめたもので、相手があなたを好きな確率ではありません。応答の質、自己開示、対立からの回復に関する研究を、信号を選ぶために使っています。以下の数値の重み、基準点 32、サンプルの閾値は製品としてのルールで、感情ラベル付きデータでは較正していません。研究の出典、適用範囲、設計上の取捨選択は [採点研究の説明](docs/SCORING-RESEARCH.md)（中国語）をご覧ください。アップグレード後は過去の推移も新しいルールで再計算されるため、新旧ルールのスコアは直接比較しないでください。

### 計算式

$$
S_0=\mathrm{clamp}\!\left(\mathrm{round}(38+W+I-C-T+R),0,100\right)
$$

$T_t,T_s$ を相手と自分の採点可能なターン数、$n_q,n_{\mathrm{sh}},n_{\mathrm{emo}},n_{\mathrm{bnd}}$ を、相手のターンのうち質問、開示、個人的な気持ちの開示、明確な否定または境界線を含むターン数とします。気持ちの開示は開示の一部なので、$n_{\mathrm{emo}}\le n_{\mathrm{sh}}$ です。各種の信号は 1 ターンにつき最大 1 回だけ数え、手動で除外した根拠は数えません。画面には確認用にメッセージごとの根拠が残ります。

ポジティブな表現はメッセージごとに段階を判定します。一般的な礼儀や絵文字は重み 1、相手から自分への支持や具体的な感謝は 4、直接的な親しみの表現は 6 です。$p_t$ を相手の第 $t$ ターンで除外されていないポジティブ表現の最大の重み（該当なしは 0）とします。同じターンの感謝と親しみの表現は重ねて数えません。画面のポジティブ表現の件数には礼儀表現も含まれるため、親しみの表現の回数としては読めません。

$n_{\mathrm{resp}}$ は、有効な回答、提案の受け入れ、話題の引き継ぎがあったターンの和集合です。同じターンが回答と引き継ぎの両方に当たっても 1 回と数えます。除外されていない摩擦や明確な否定の根拠が残るターンには、有効な応答の加点は付きません。

$$
\begin{aligned}
P&=\min(18,\sum_t p_t),\quad Q=\min(10,2n_q)\\
H&=\min(12,2.5n_{\mathrm{sh}}+1.5n_{\mathrm{emo}})\\
A&=\min(12,12n_{\mathrm{resp}}/\max(4,T_t))\\
W&=\min(45,P+Q+H+A)
\end{aligned}
$$

$a_t,a_s$ を双方が会話のまとまりを始めた回数、$n_{\mathrm{perf}},n_{\mathrm{low}}$ をおざなりなターンと情報量の少ないターンの数、$n_c$ を摩擦のあるターンの数、$n_{\mathrm{rep}}$ を相手の説明または和解のターンの数とし、$G$ は同じ会話のまとまりに相手の摩擦のターンが 2 回以上あることを表します。

$$
\begin{aligned}
I&=\begin{cases}4a_t/(a_t+a_s+4),&T_t>0\land T_s>0\\0,&\text{その他}\end{cases}\\
E&=T_t>0\ ?\ \min(1,(n_{\mathrm{perf}}+n_{\mathrm{low}})/T_t):0\\
C&=\min(60,24n_{\mathrm{bnd}}+\mathrm{round}(16E))\\
T&=\begin{cases}\min(24,12n_c),&G\\\min(8,8n_c),&\text{その他}\end{cases}\\
R&=\min(4,2n_{\mathrm{rep}})
\end{aligned}
$$

| 項目 | ルール |
| --- | --- |
| 基礎点 | 38 |
| ポジティブ表現 P | 同じターンでは最も強い段階だけを採用：礼儀・絵文字 +1、支持・具体的な感謝 +4、直接的な親しみ +6。合計最大 +18 |
| 質問 Q | 1 ターンにつき +2、最大 +10 |
| 自己開示 H | 開示のあるターンごとに +2.5、気持ちの開示ならさらに +1.5。開示の合計は最大 +12 |
| 有効な応答 A | 12 × 有効な応答のターン数 ÷ max(4, 相手のターン数)、最大 +12。ポジティブ 4 項目の合計は最大 +45 |
| 説明と和解 R | 1 ターンにつき +2、最大 +4 |
| 否定または境界線 | 1 ターンにつき −24。明確な否定または境界線がある場合、最終スコアは最大 32 |
| おざなり・情報量が少ない | 相手のターンに占める割合 × 16 を四捨五入して減点。1 ターンにつき 1 種類だけ。否定と合わせて最大 −60 |
| 返信の遅れとメッセージ数の偏り | 統計として残すが、直接の加点・減点はしない。相手のターンが 0 回、または 1 回だけの返信でも、それ自体では減点しない |
| 自分から話しかける I | 双方にターンがある場合、上記の比率で加点（上限は 4 未満）。話しかけが少なくても減点しない |
| 通常の摩擦 T | 最大 −8 |
| 強い摩擦 T | 最大 −24、最終スコアの上限 48。説明はペナルティを増やさず、強い摩擦も発動しない |

同じ人が 3 分以内の間隔で続けて送ったメッセージは、1 つのターンにまとめます。
最初の発言、または前のターンの終わりから 120 分以上空いた発言で、新しい会話のまとまりが始まります。
返信の遅れは、自分のまとめたターンの最後のメッセージから、相手の返信ターンの最初のメッセージまでで計ります。
まず時系列全体を判定してから、話しかけ、回答、遅れを発生した日付に割り当てます。日ごとのターンは午前 0 時で区切りますが、同じ会話のまとまりの文脈は保ちます。
タイムゾーンのない時刻は上海時間として解釈し、Unix 秒・ミリ秒と、タイムゾーンが明示された時刻は変換してから並べます。
強い摩擦には、同じまとまりの中に相手の摩擦のターンが 2 回以上必要です。
説明は確認できる文脈の手がかりとして残し、新たな摩擦とはみなさず、それだけで和解したともみなしません。
比較できる時刻がない場合は分けて扱い、対立が続いていると推測しないようにします。
摩擦、説明、明確な否定のターンは、おざなり・情報量が少ないとして重ねて数えません。

質問は文節ごとに判定し、礼儀としての感謝があっても、別の文節にある実際の質問は打ち消されません。
手動修正は、質問、開示、ポジティブ、否定、おざなり、情報量が少ない、摩擦、説明、回答または提案の受け入れ、引き継ぎまたは情報の補足、の 10 種類に対応しています。
ターンの信号には最初の元メッセージを表示し、修正にはそのターンの構成メッセージと原文を保存します。後からより前のメッセージが追加されても元の根拠との関連は保たれ、新しい独立した一致が出たり元のテキストが変わったりした場合は判定し直します。復元にも対応しています。
メッセージ単位の修正でも、その時点の原文のスナップショットを保存します。同じメッセージ ID のテキストが変わった場合、古いテキストに対する除外の判断は引き継ぎません。

記録のある日で、$T_t=0$ または $T_s+T_t<4$ を満たし、かつポジティブ、質問、開示、有効な応答、否定、摩擦、おざなり、情報量が少ない、のいずれの信号もない場合は、$S_0$ を 32 で置き換え、置き換え後のスコアを $S_1$ とします。それ以外は $S_1=S_0$ です。低頻度の条件にはまとめた後の双方のターン数を使うため、1 つの返信を複数のメッセージに分けても置き換えは解除されません。

相手のターンが 6 回未満の場合は、32 を超える部分だけをサンプル数に応じて縮小します。

$$
S_2=\begin{cases}
\mathrm{round}(32+(S_1-32)\min(1,T_t/6)),&S_1>32\\
S_1,&S_1\le32
\end{cases}
$$

最後に、$G$ が成り立つ場合は $S=\min(S_2,48)$、それ以外は $S=S_2$ とします。$n_{\mathrm{bnd}}>0$ の場合は、さらに $S\leftarrow\min(S,32)$ を適用します。明確な拒否は他の加点で打ち消されず、32 未満の否定的なスコアがサンプル不足を理由に引き上げられることもありません。32 は根拠が不足しているときの表示上の基準点で、32% の好意を意味しません。記録がまったくない日は欠測として表示します。

### 文脈とやり取りへの関与

「随便你」（好きにして）、「都行看你」（どれでもいい、任せる）、「你看着办」（そっちで決めて）だけの場合は、選択を任せたものとして中立に扱い、それ以外の場合は原文を残して確認に回します。会話のまとまりをまたぐこと自体では摩擦の減点にならず、独立した明確な非難や連絡をやめてほしいという要求は、それぞれ別に判定します。

採点では、システムメッセージ、テキスト以外のメディアの記録、プレースホルダーだけのテキストを除外します。メディアは元のチャット画面に残り、ファイル名、通話のプレースホルダー、システムの通知から誰が話しかけたかを判断することはなく、画像の内容も読み取りません。
口語的な自己開示は、「我俩吃了」（2 人で食べた）、「我老看」（いつも見てる）、「我就记得」（覚えてる）などの表現に対応しています。
相手に何かをするよう求める文は、開示とポジティブの判定の両方から除外します。同じメッセージ内の独立した本人の経験やポジティブな表現は残します。
「没有没有」（いやいや）や、第三者について尋ねる文は、自分への質問として数えません。
一人称の実際の気持ち（うれしい、悲しい、緊張しているなど）は気持ちの開示として数えられますが、引用、他人への指示、仮定の表現はこの段階に含めません。気持ちの正負や強さで追加の加点はしません。連絡をやめてほしいという丁寧な依頼も明確な境界線です。「不是不喜欢你」（嫌いなわけじゃない）のように拒否を打ち消してなだめる表現は、拒否とは判定しません。

短い返信は、直前の質問、提案、隣接する話題と照らして判定します。質問に答える、提案を受け入れる、具体的な評価を付け加える、話題を引き継ぐ短い文は、有効な応答の候補になります。一度だけの相づちや笑いは中立とし、相手のターンが 3 回続けて有効な応答を欠く場合にだけ短い返信のペナルティを適用します。普通に忙しい、寝る、おやすみ、その場の会話を終える、といった表現は中立とし、有効な応答がない連続回数にも数えません。仕事、顧客、機器などの外部のストレスへの不満は、自分に向けた言い回しがない限り、2 人の関係の摩擦とはみなしません。
相手が自分の直前のターンにそのまま答えている場合は、2 時間以上空いていても、そのターンの文脈を回答と引き継ぎの判定に使います。2 時間での区切りは、話しかけと同じまとまり内の摩擦の統計に引き続き使います。
回答、提案の受け入れ、引き継ぎの指標は、原文を開いて確認・除外・復元できます。
時間、場所、数量、はい・いいえの質問は、それぞれ答えの特徴と照合し、判定済みの出来事の動作とも照らし合わせます。
たとえば、家を出た時間を尋ねた場合、返信に出てくるスマートフォンを買った時間は回答として数えませんが、独立した時間だけの短い答えは残します。
話題の引き継ぎには、語の関連または同じ種類の話題が必要です。「人多」（混んでる）「美味」（おいしい）のような孤立した語句や、「的」で終わる語句は、そのままでは一致とみなしません。
自分が直前のターンで気持ちや良い知らせを伝え、相手がその文脈に合った理解、支持、祝福を返した場合は、引き継ぎの信号として数えられます。引き継ぎと同じ修正の仕組みを使い、有効な応答の和集合に含めますが、別項目として重ねて加点はしません。文脈のない一般的な褒め言葉は、自動的に支持的な応答には格上げしません。

やり取り指標ページでは、関与スコアとポジティブ表現の件数を分けて表示します。関与スコアは同じ式でポジティブな言い回しの項目を 0 にして計算し、回答、質問、開示、ターンなどの行動の手がかりを残します。
ポジティブ表現は、根拠と段階のラベルを付けて別に一覧表示します。従来の好感手がかりの項目とグラフは、ポジティブな項目を含むスコアを引き続き使います。
場面は、仕事、日常、混合、未分類のルールで判定し、それぞれの話しかけの回数と場面別の結果を表示します。
場面のラベルは確認用で、総合的な重みはまだ場面ごとに分けていません。場面別の結果は会話のまとまり単位で集計し、同じまとまりの普通の返信はそのまとまりに含めます。仕事にも日常にも当てはまる語がないまとまりは未分類とします。

| 表示項目 | 計算範囲 |
| --- | --- |
| やり取りの関与スコア | 選んだ 2 人の採点可能なテキスト全体。ポジティブな言い回しの項目を 0 にして再計算 |
| ポジティブ表現の件数 | ポジティブ語彙に一致し、手動で除外されていない相手のメッセージ。礼儀、支持、直接的な親しみを含む |
| 質問への応答／話題の引き継ぎのターン | 直前のターンの文脈と合わせて判定。1 件ずつ確認・修正できる |
| 関与スコアの平均 | 有効な記録のある日の関与スコアの単純平均 |
| 好感手がかりの日別スコアと推移グラフ | ポジティブな項目を含む v2.3 のスコア。月・年はターン数で重み付け |
| 場面別の関与スコア | 仕事、日常、混合の会話のまとまりをそれぞれ採点し直したもの |

同じ記録でも、記録全体でのスコア、日ごとの単純平均、月・年の重み付きスコアは集計範囲が異なるため、比較するときは画面のラベルを確認してください。ルールで判定した「情報量が少ない」「仕事」などの分類は、原文と照らして確認できます。

### 月・年の集計

$$
w_d=\max(1,T_t^{(d)}),\quad
R=\sum_d T_t^{(d)},\quad
\bar S=\frac{\sum_d S_dw_d}{\sum_d w_d}
$$

$$
M=\begin{cases}
\mathrm{round}(32+(\bar S-32)R/20),&R<20\land\bar S>32\\
\mathrm{round}(\bar S),&\text{その他}
\end{cases}
$$

重みの合計と、相手の実際の総ターン数 $R$ は別々に数えます。相手のターンが 0 回の記録日は重み 1 ですが、$R$ は増えません。月と年はどちらも同じ 20 ターンの縮小閾値を使います。ここでの $S_d$ はすでに日ごとのサンプル数による縮小を受けています。月・年での再度の縮小は独立した保守的な集計ルールで、統計的な信頼区間ではありません。
