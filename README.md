# Relationship Notes for DSH

关系手记 3.1：本地优先的联系人档案、互动证据与沟通草稿插件。

## 使用

- 在 DSH「定制模块」打开关系手记，导入聊天文件并确认双方身份。
- 在联系人档案中核对模型待确认条目，再接受、编辑、归档或删除。沟通风格、边界、待跟进和推测线索分别呈现。
- 在设置中维护“我”的语气、口癖、兴趣、计划、边界和认可样例。回复生成参考这些信息以及真诚表达、尊重边界、不用试探测试关系等原则。
- 互动评分可以展开原文，标记误识别并恢复；指数是表达线索汇总，不是好感概率。
- 回复栏可选择真诚/轻松/简短风格，并主动生成带引用和不确定性的多种可能解释及回复思路。
- 需要 DSH 主对话读取资料时，显式开启“允许 DSH 读取当前联系人”。可读取已确认档案、搜索最近最多 500 条共享消息，并提出待确认候选。共享范围是当前本机 DSH 宿主中的工具对话，参见 [档案工具说明](PROFILE-TOOLS.md)。
- 项目备份可以选择包含或不包含媒体；旧版备份仍可恢复。

微信/QQ 监听、独立替代 ExportWeChat 读取、自动发送和主动搭话暂缓开发，只有 [研究方案](CAPTURE-RESEARCH.md)。现有 ExportWeChat JSON/HTML 文件导入继续可用。

## 构建与验证

使用 Node.js 24 和 pnpm：

```sh
pnpm install --frozen-lockfile
pnpm run build
pnpm test
```

构建使用显式 ESM 模块与 esbuild，不依赖仓库之外的原型文件。`client.js` 是生成产物，源码仓库不提交；安装包附带生成产物。容器契约是 `inject: ['locale', 'subdsh']`，注册 ID `relationship-notes`。

## 数据与模型

聊天、档案、草稿和本人画像保存在浏览器本机 IndexedDB。用户主动调用模型时，选定上下文和已确认资料会交给 DSH 配置的模型服务。开启档案共享时，当前联系人的有界快照会暂存在宿主内存，关闭/切换后撤销，停止同步后 60 秒过期；宿主不落盘保存此快照。

导入工具使用内存队列；重启前应确认消费完成，见 [导入队列设计](IMPORT-QUEUE-DECISION.md)。备份含聊天资料，应自行妥善保存。仓库不包含用户聊天导出、联系人档案、媒体、凭据或个人备份。
